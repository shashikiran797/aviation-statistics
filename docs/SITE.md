## Deploying to GitHub Pages

The deployable site is the `web/` folder. All URLs in the app are relative, so it works under
`https://<user>.github.io/<repo>/` without changes. Two things are not in git and must exist at deploy time:

- `web/vendor/` (gitignored): produced by `make vendor`. If missing, the app falls back to CDN builds (works, but needs internet).
- `web/data/` (ignored by the `data/` rule in `.gitignore`): the published Parquet. It is about 10 MB.

### One-time setup

1. **Decide where `web/data` comes from.** Simplest: commit it. Add exceptions to `.gitignore` and commit the build output.
   ```gitignore
   data/
   !web/data/
   ```
   ```bash
   make publish && git add -f web/data && git commit -m "Publish data" && git push origin main
   ```
   (The alternative is to run `make update` in CI, which re-crawls dgca.gov.in on every deploy and is slower and more fragile.)
2. **Enable Pages:** repository **Settings > Pages > Build and deployment > Source: GitHub Actions**.
3. **Add the workflow** `.github/workflows/pages.yml`:
   ```yaml
   name: Deploy site
   on:
     push: { branches: [main] }
     workflow_dispatch:
   permissions: { contents: read, pages: write, id-token: write }
   concurrency: { group: pages, cancel-in-progress: true }
   jobs:
     deploy:
       runs-on: ubuntu-latest
       environment: { name: github-pages, url: "${{ steps.deploy.outputs.page_url }}" }
       steps:
         - uses: actions/checkout@v4
         - uses: actions/setup-node@v4
           with: { node-version: 20 }
         - run: ./scripts/vendor.sh
         - run: test -f web/data/latest.json   # fail loudly if the data was not committed
         - uses: actions/upload-pages-artifact@v3
           with: { path: web }
         - id: deploy
           uses: actions/deploy-pages@v4
   ```
4. Push to `main`. The site appears at `https://<user>.github.io/<repo>/` (this repo: `https://shashikiran797.github.io/aviation-statistics/`).

### Notes

- **Range requests:** GitHub Pages supports HTTP Range, which DuckDB-WASM needs for Parquet. `scripts/serve.py` mimics this locally.
- **HTTPS:** Pages is HTTPS, so the service worker registers and the app is installable and works offline after a first visit.
- **Updating data:** run `make update`, commit `web/data`, push. The old version directory can be deleted; `latest.json` points at the current one.
- **Size:** `web/vendor` is ~39 MB and `web/data` ~10 MB, well under the 1 GB Pages limit.
- **Scheduled refresh (optional):** a weekly workflow can run `make update`, commit changes to `web/data` and let the push trigger the deploy.
  Run AI repair tasks locally; CI does not run them.
